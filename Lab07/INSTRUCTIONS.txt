1. Test the control unit
-----------------------
Compile and run the self-checking tests. The test covers every don't-care
opcode combination for the supported instruction patterns, including ADDI
and MOVZ, and checks unmatched opcodes return default controls.

    iverilog -o SingleCycleControlTest SingleCycleControl.v SingleCycleControlTest.v
    gtkwave singlecyclecontrol.vcd

The terminal should report "All control-unit tests passed". In GTKWave, inspect
the opcode and control-signal transitions. Close GTKWave before running the
processor test if you prefer a separate waveform window.

2. Test the complete processor
-----------------------------
Compile all modules used by the top-level processor and its testbench:

    iverilog -o SingleCycleProcTest_v ALU.v DataMemory.v InstructionMemory.v NextPClogic.v RegisterFile.v SignExtender.v SingleCycleControl.v SingleCycleProc.v SingleCycleProcTest.v
    gtkwave singlecycle.vcd

Both programs must pass. Program 1 checks the original instruction set and
must complete with result 0xF. Program 2 runs after Program 1 and must report
"MOVZ/store/load Program 2 passed" with result 0x123456789abcdef0. It builds
that value from four MOVZ instructions, combines the pieces with ORR, stores
the result at byte address 0x28, and loads it into X10.
